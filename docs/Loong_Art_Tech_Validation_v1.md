# 《Loong》第一版美术技术验证执行文档（V1.0）

**项目：** Loong｜UE5.8.3｜风格化3D肉鸽战斗与龙族经营  
**参考目标：** 用户提供的战斗概念图；它是画面风格参考，并非现成的可运行3D场景。  
**核心方向：** Stylized Fantasy 3D / Painterly Hand-Painted Look / 斜俯视 / 插画式光影 / 2D精致卡牌UI。  
**本轮目标：** 先完成一个可运行、可截图、可测帧率的战斗视觉验证场景，暂不批量制作正式游戏资产。

## 1. 验证目标与边界

做一段 **30—60秒战斗演示**：玩家WASD移动并自动攻击；一只风系伴战龙跟随并施放旋风；20—30只占位怪靠近玩家；画面可弹出一次升级三选一卡牌。场景为一小片奇幻森林遗迹。

**必须达到：** ①一眼认出人物、龙与敌人；②真实3D具备柔和手绘插画感，而不是UE默认写实感或塑料卡通感；③旋风、箭矢与怪群可读；④UI和场景视觉统一；⑤PC和移动端有明确画质降级方案。

**本轮不做：** 十几种龙、完整剧情、开放世界、大地图、全套建筑美术、100只高精怪物、完整手机适配或正式商业级配音。现有`L_Base`、基地建造、存档和旧蓝图不动。

## 2. UE5目标画面标准

| 维度 | V1目标 | 具体执行原则 |
|---|---|---|
| 摄像机 | 固定斜俯视3D | 优先测试正交投影；初始Pitch约-55°至-60°、Yaw约-45°、Orthographic Width约2600cm；依人物屏幕尺寸微调。若正交空间感不足，再对比低FOV透视。 |
| 构图 | 人物视觉中心附近，战场向四周延伸 | 角色、伴战龙、敌人和主要技能不能被植被/UI长期遮住。 |
| 造型 | 大轮廓、适度夸张、强剪影 | 保留头发、武器、龙翼、角和尾巴等识别点；不追求皮肤毛孔和微观真实细节。 |
| 材质 | 手绘BaseColor、克制的PBR | 适当保留明暗体积；少镜面反射、少金属噪点、少程序化脏污。 |
| 光照 | 暖主光+清凉环境填光 | 柔和接触阴影、清晰读形，避免写实黑影与强烈自动曝光跳变。 |
| 地表 | 有设计的色块与纹理 | 草地、泥土、石块、遗迹使用手绘纹理、顶点色或材质混合；不要照片扫描感。 |
| VFX | 清晰的风系能量形体 | 旋风主轮廓、内外旋转层、叶片/碎石次级粒子，优先清晰而非粒子数量。 |
| UI | 羊皮纸/雕木/兽骨/符文语汇 | 升级卡牌、角色HUD使用2D资产与UMG；中文排版需清晰。 |
| 性能 | 原型先测PC 1080p 60fps | 中端PC目标帧时间≤16.7ms；手机单独制作30fps档（≤33.3ms），指标为验收目标而非保证。 |

**参考配色（只作为方向，不是锁死数值）：** 森林草绿`#789351`、暖金土`#B68B54`、阴影深绿`#324B3F`、遗迹岩灰`#807F73`、风系浅青绿`#B7E7AE`、龙纹蓝青`#4EA6AB`。场景低饱和层次衬托龙和技能的鲜明颜色。

**严格避开：** 真实扫描贴图、油亮塑胶表面、过强描边、灰暗高反差影视调色、过多Bloom、密集噪点、角色和怪物融入地面、遮挡操作的粒子与UI。

**初始预算（需要根据目标设备实测调整，非强制上限）：** 玩家约15k—30k三角面；龙约8k—20k；普通怪约3k—10k；常见单体小场景道具约0.5k—5k。角色/龙贴图优先1K—2K，重复道具优先512—1K，场景可用共享材质和贴图集。按可见大小分配预算，不要先堆看不见的细节。

**模型交付约定：** UE尺寸单位厘米；Z轴向上，正面方向统一；人物、龙和建筑/道具的Pivot约定在提交前确定并写入说明；模型提供可用UV、合理碰撞和LOD方案；需要骨骼动画的模型提供骨骼与基础动作。资源统一命名，如`SK_Hero_Test`、`SK_Dragon_Wind_A`、`SM_Ruin_Arch_A`、`MI_Env_Rock_A`、`NS_WindWhirl`、`WBP_LevelUp_ArtTest`。可以使用FBX/glTF等UE兼容格式，但导入后必须检查法线、切线、材质和动画。

**素材获取策略：** 概念稿可用AI辅助；正式可动画3D模型仍需建模、拓扑、UV和绑定检查。外包或商店素材需确认商业使用、修改、再分发以及训练素材相关授权，不把AI概念图直接当作现成可用3D资产。

## 4. 材质、光照和特效技术规范

### 4.1 可复用材质

先制作3类Master Material或等效实例体系：`M_Master_Character`（人物/龙/怪）、`M_Master_Environment`（岩石树木木料）、`M_Master_Ground`（草地/泥土）。使用材质实例调整颜色与参数，不要每个资产单独重写Shader。

- **基础材质：** Default Lit为起点，BaseColor自带手绘的冷暖变化和体积明暗；Roughness多数偏高，Metallic多数为0，法线与AO适量使用，避免油亮感。
- **形体：** 大面积色块、边缘略提亮、接缝与凹处轻微压暗；角色可试少量Fresnel/Rim，但不做通体强发光描边。
- **地面：** 两到三组手绘地表纹理混合，添加可控大尺度颜色变化；减少重复平铺痕迹和细碎真实噪声。
- **UI：** 完全独立的2D纹理和九宫格切片，不用场景3D材质去仿UI。

### 4.2 场景光照

设置一个可重复的固定光照基准：偏暖Directional Light + 偏冷/中性Sky Light + 合适的环境雾与Post Process Volume。初期锁定或收紧自动曝光，以便比较材质；适当微调白平衡、对比度和饱和度。不要靠大量Bloom和后期滤镜掩盖材质问题。

推荐首先完成3张同角度截图：**仅基本光照、加入手绘材质、加入特效UI**，逐步验证哪个环节真正增加插画感。手机画质单独验证，不以PC最高档画面作为手机必须复现的标准。

### 4.3 风系旋风（示范特效）

使用Niagara与简化网格/贴图组合：底部旋转风纹 + 1—2层带状漩涡 + 受控树叶/碎石 + 轻度边缘发光。视觉风暴半径和实际伤害判定半径需分别标示并尽量对应。让角色和怪物的轮廓在大招期间仍可读；避免透明粒子层层叠加导致移动端Overdraw过高。手机档降低粒子数量、材质层数和屏幕覆盖面积。

## 5. 第一张战斗测试地图怎么搭

**地图名：** `Content/Loong/Maps/L_Combat_ArtTest`。新建独立地图，不改`L_Base`。测试空间约60×60米，仅为布景及性能验证范围；真正可见战斗视野比整张测试地图小。

按顺序执行：

1. **灰盒阶段：** 地面、少量体块障碍、测试人物、镜头；锁定人物画面占比和相机俯仰。基地200cm建造网格规则不应强加给战斗地形。
2. **构图阶段：** 布置左侧石碑与遗迹、中间留清晰战斗区、边缘用森林/岩石形成深度；测试树冠遮挡策略（淡出、半透明或合理布景）。
3. **色彩阶段：** 用少量手绘材质替换灰盒；保证角色、龙、怪的明度/色相区别。
4. **战斗阶段：** 接入已有或在开发中的C++自动战斗测试接口，投放20—30只敌人；使用人物普攻、风龙旋风、受击反馈。
5. **UI阶段：** 添加生命、经验、计时和升级三选一测试UI；菜单弹出时暂停战斗，但场景构图保持完整。
6. **验证阶段：** 在固定位置导出1920×1080截图、30—60秒视频及`stat unit`、`stat gpu`等性能记录；再测试较低画质与手机平台方案。

**镜头起始参数为调试建议，而非终值：** Pitch约-55°、Yaw约-45°、正交宽度约2600cm。以可见角色高度约70—110像素（1080p截图）和怪群识别为目标微调。若正交投影使风龙飞行缺少层次，可对比低FOV透视镜头，但不要同时随意更改多个变量。

## 6. AI概念制作与外包任务描述

### 6.1 通用风格提示词（英文，可用于AI概念稿）

> Stylized fantasy action roguelite art direction, fully 3D characters and environment with a premium hand-painted illustration appearance, elevated three-quarter top-down camera, expressive silhouettes, lush fantasy forest ruins, warm sunlight and cool green ambient shadows, painterly color blocks, softly sculpted forms, readable combat effects, ornate fantasy game UI, rich but organized composition, clear hero-versus-enemy readability, production-minded visual development, not photorealistic, no glossy plastic materials, no excessive outlines, no gritty photographic textures. Original designs, no imitation of named games or existing characters.

### 6.2 单项任务（AI/外包）

- **玩家角色：** “原创奇幻冒险者，夸张武器与头发剪影，适合高角度镜头辨认。提供正/侧/背三视图、关键配色、远景小尺寸测试，不以近景写实脸部为重点。”
- **风系龙：** “原创轻盈幼年风龙，羽翼或叶片形翼缘、青绿和乳白配色；提供正/侧/背结构图、飞行/施法动作关键帧、3D建模可执行的翅膀与尾巴结构。”
- **森林遗迹：** “可模块化拼装的奇幻手绘森林，遗迹石碑、岩块、草丛、暖色火盆，昼间斜俯视镜头，提供模块拆分图、材质样张和颜色分层。”
- **旋风技能：** “插画式风系魔法，明确内外流向与半径，青白风纹、少量叶片碎石，提供起手/持续/结束三帧和透明背景粒子元素。”
- **升级卡牌：** “奇幻羊皮纸+木雕/龙骨装饰，三张升级卡，符文技能图标，单张卡在1080p和手机缩放下文字易读；输出分层边框、底纹、图标和按钮状态。”

**正式外包交付必须包含：** 风格基准图、模型源文件、导出模型、贴图、基础动作或特效分层、导入说明及授权范围。每件资产先经过UE实际镜头测试，再扩展同系列。

## 7. Codex与美术工作分工

**Codex负责：** 保持C++战斗系统独立于基地系统；新建/配置独立艺术测试关卡的必要代码；参数化镜头、战斗试验开关、假人刷怪、性能统计与简单测试UI；搭建UE编辑器脚本来批量导入/校验模型贴图（如适用）；真实编译并修错。

**人或美术AI辅助负责：** 视觉规范、概念设计、3D建模、UV/贴图、骨骼动画、手绘VFX图样、UI原画和视觉验收。Codex不能凭修改C++就自动产出高完成度的3D美术，也不应将概念图声称为可直接使用的模型。

**给Codex的第一条任务：**

> 请在Loong项目中制定并实现`L_Combat_ArtTest`所需的最小技术支撑。不要修改`L_Base`或稳定建造/存档蓝图；先检查Git状态。优先复用已有角色移动、镜头及肉鸽战斗接口。为测试地图提供可配置的斜俯视镜头参数、1名玩家、1个可挂载的伴战龙占位Actor、两类占位敌人、20—30敌人的性能场景、可切换风系Niagara占位效果与升级UI测试入口。代码与资源的职责分离；不能安全自动生成.umap/.uasset时，请明确给出UE5中文版编辑器操作。输出新增文件、UBT编译日志、可执行测试结果、PIE验证步骤与性能指标，不要擅自覆盖已有资产。

## 8. 执行顺序与里程碑

| 里程碑 | 目标产物 | 通过条件 |
|---|---|---|
| M0 视觉基准 | 参考图拆解、色板、龙/角色风格页 | 团队能用相同关键词解释“像什么、不像什么” |
| M1 斜俯视灰盒 | 独立测试地图、镜头和怪群站位 | 人物/龙/怪在1080p画面清楚，视角固定 |
| M2 材质光照 | 一套角色/地面/岩石手绘材质 | 不靠UI和粒子也有明显插画质感 |
| M3 核心资产 | 1人物、1风龙、2敌人、场景模块 | 动画能用，近远景识别清楚 |
| M4 技能UI | 风系旋风、人物弹道、受击、三选一卡牌 | 战斗信息明确，UI不遮挡主要操作 |
| M5 优化验收 | 截图、视频、性能记录、问题清单 | PC目标档可运行；手机降级方案明确 |

对于小团队，先做**一到两周的灰盒与LookDev验证**；达到满意风格后再投入数周打磨正式的高质量美术切片。不要预先承诺一周内交付参考图级别的全部场景。

## 9. 验收表与通过门槛

1. 在1080p正常战斗镜头下，玩家、龙、小怪和重怪剪影易辨认，缩至50%预览仍可看出主体。
2. 地面、树、石、遗迹的色彩和纹理属于同一套手绘语言，没有照片扫描感与塑胶高光。
3. 旋风技能有明确轮廓、起止、半径提示，施放期间依旧可以读出敌人和危险区域。
4. 屏幕出现20—30敌人时，战斗主角、伴战龙和攻击方向不被视觉噪声淹没。
5. 升级卡牌可点击，文字、技能图标、选中状态清楚；至少测试1080p与较窄屏幕布局。
6. PC参考画质实测帧时间并保存记录；手机至少完成一次平台画质可行性评估，不能只用PC帧率代表手机。
7. 与`L_Base`及基地存档系统隔离；现有B键建造、基地UI及存档功能不回退。
8. Git单独保存美术测试地图、代码、材质、资源与截图，形成可回退的视觉基准版本。

**决策门槛：** 只有M0—M5完成并经过同一镜头对照参考图审查，才锁定美术风格并批量外包/生产龙、怪、建筑和地图。未达标时先查造型、贴图、光照或构图，不要盲目增加模型面数和粒子数量。

## 10. 当前立刻执行的三项任务

1. **建立`L_Combat_ArtTest`独立灰盒地图，并保存当前斜俯视相机截图。**
2. **先制作风龙+岩石/草地这两类材质样例，验证“精致手绘感”是否真的出现在实时UE画面。**
3. **用20只敌人加一个风系旋风特效测试可读性与性能，再决定第一批正式资源预算。**
